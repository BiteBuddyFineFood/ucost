# P2 / P3 实施与升级说明

日期：2026-11-12。本文描述本次实际实现，与待实施的 v2 方案分开保存。

## P2

- 新增 RecordGroup、ListSettlement；清单总预算、核算方式、结束时间；账单购物来源独立于展示分组；省钱保留清单来源、结算来源及被替代标记。
- 历史关联按真实清单/物品 ID 回填，同名清单不合并，迁移不产生账单或省钱金额。多购物项引用同一主支出的异常旧链接不自动回填唯一来源。
- 账本和省钱本独立保存分组/平铺偏好。先筛选再分组，展示日期范围、数量、当前筛选小计、收入/支出/退款/净支出；可查看全组、手动建组和改名、移入移出、解散。按组分页，组内每次展开 20 条。保留原全量快照架构，尚未将全量同步改成服务端游标分页。
- 清单支持预算合计一次性复制、已购实付/关联账本/退款/未购/已购未记账提示。全部记账逐项填写实付、日期、账户、分类、优惠、档案；统一日期/账户；排除已放弃，跳过已入账，支持零元档案、关联已有匹配支出、复用档案。最多 100 项，预览后整批事务提交。
- 预算结算要求采购结束、全部购买/放弃、实付明确、无来源含混的关联手工省钱；保存预算、实付和成员快照。`max(预算-实付,0)` 不减退款。系统商品优惠/购物决定省钱使用独立 superseded 标记，保留原 suppressed 停用意图。
- 重新打开、预算变更、购买修正、退款、删账等使结算待核对；重新确认更新同一结算、省钱记录。切回商品模式撤销预算结余，解除替代标记。全部页面统一使用 effectiveSaving 排除待核对、撤销、主动停用和被替代项。

## P3

- 统一任务网关覆盖 suggest、process、analysis、polish、classification、个人连接测试。直接调用推理函数必须具有网关任务上下文。
- 上海日期每用户每日 10 项系统任务，短事务原子预占；成功消费，完全失败释放；10 草稿的内部并行及每个失败项最多一次重试合计只扣一次；分类最多 50 条；分析内部多阶段仍只扣一次。查看缓存分析、保存结果、手动确认不扣次。
- 固定任务输入及版本、operationId 防重、24 小时结果有效期、步骤进度、执行超时及租约；过期任务释放原日期预占，迟到响应不能重新扣次。普通任务每分钟最多 30 项、每用户最多两个执行任务，个人测试每分钟最多五次。
- UserAiConfig 独立存储 AES-256-GCM 密文；普通快照只返回服务模式、配置可用性、额度和重置时间。模型名仅在个人配置表单提供，API 不回传明文密钥。
- 个人服务不扣系统额度，失败不自动回退。地址须 HTTPS，禁止内网/回环/元数据，解析所有地址并校验、连接固定验证后的 IP，拒绝重定向。部署者可显式打开本地模型选项，普通用户无法自行开放内网。
- 分类建议按已有分类和类型校验，规则优先，无合适分类保留未分类。建议持久化在任务结果，当前浏览器刷新可恢复核对面板；确认逐项选择，拒绝记录过期/归档分类/越权引用，只应用分类字段。

## 升级

1. 备份与演练：`node scripts/verify-upgrade.mjs`。脚本通过 SQLite 在线备份 API 创建一致性备份（包括 WAL 中已提交数据），在备份副本和空库执行全部迁移，对比核心记录数量、收支和有效省钱。备份在 `data/p2-p3-verification/`，不会直接迁移源库。建议停服务后同时保存 uploads。
2. 停止应用，执行 `npm.cmd run db:migrate`、`npm.cmd run db:generate`，再启动。Windows 上运行中的应用可能锁住 Prisma 引擎 DLL，生成前需停止持有该文件的 Node 服务。
3. 本次已在演练通过后对现有开发库执行增量迁移。原始数据库备份路径见 `data/p2-p3-verification/migration-report.json`。
4. 设置个人服务前，在服务端 `.env` 配置 `AI_CONFIG_ENCRYPTION_KEY`，为 32 字节随机数的 64 位十六进制。可用 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 本地生成，将值自行写入 `.env` 并安全备份；此密钥不可写入业务导出或 Git。更换主密钥前须重新加密已有配置。

   本次开发环境已自动生成该主密钥并仅保存至本地 `.env`，未输出或写入文档。重启后即可保存个人配置；请将 `.env` 纳入服务端安全备份。
5. 本地模型仅在部署者设置 `AI_ALLOW_LOCAL_ENDPOINTS=true` 后允许 localhost/127.0.0.1/::1，默认关闭。启用个人配置后可在设置页检查连接；系统检查只检查配置，不发起付费推理。
6. 现有仓库忽略 `.sql`、`.env.example`、README 和 docs；分发或提交时必须显式包含本次迁移和所需历史迁移，不能只携带 schema 后对旧库运行 db push。迁移文件为 `prisma/migrations/20261112130000_p2_p3_groups_ai/migration.sql`。
7. 回退使用匹配的旧代码、数据库备份和 uploads；不要让旧代码继续写入已使用新字段的数据库。升级后有新记录时先另外备份并核对，避免覆盖新写入。
